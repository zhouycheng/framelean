01 / 产品目标

让用户描述结果，让系统完成处理

普通用户通过预设完成压缩和转换；需要批量处理的人管理队列与输出规则；后续由内置或外部 Agent 组合既有能力，完成内容定位、语义分段与导出。基础处理可以独立使用，智能能力按需启用。

第一层 · 产品 MVP可靠的视频压缩

导入、分析、压缩、排队、进度、取消、输出与后台续跑。

第二层 · 毕设交付多端媒体工具箱

三端基础处理，视频/音频/图片能力，可靠性实验和 AI 原型。

第三层 · 长期产品可被 Agent 驱动

内容理解、智能分段、CLI/MCP、模型适配和可复用工作流。

代表性基础任务

“把这些视频压小，方便发送。”

选择清晰度预设和目录即可执行。界面说明实际输出体积与质量取舍，并保留原文件。

代表性长期任务

“按话题分段，每段导出为通用格式。”

先分析内容并给出边界依据；按用户选择自动执行或先预览，再批量导出、命名和检查结果。

产品边界：聚焦媒体处理、理解、分段与结果交付。复杂时间线剪辑、字幕制作和调色不纳入本计划；语音转录可作为内容理解的内部数据使用。

02 / 事实与建议分开

旧材料可以沿用什么，哪些需要更新

核对项材料或当前事实本计划建议
题目与 Flutter开题报告、任务书的题目均为《媒体处理APP“FrameLean”的设计与实现》。Flutter 出现在任务书技术路线中。继续使用 Flutter，保持技术路线一致。若另有更新后的正式题目，以该版本为准。
开发起点旧材料写“在已有桌面版本上继续开发”。当前 main 的已跟踪文件仅有 .gitignore；旧成果保存在归档分支。以 main 重新开发。按能力复用旧实现与测试案例；更新论文中的实现起点、迁移方式和验证口径。
模块职责旧材料已有 Flutter 客户端、Rust 媒体引擎、媒体运行时三层设计。保留三层思想。Worker 统一持有队列与任务状态；FLL 聚焦单次媒体操作；重处理进入隔离宿主。
平台与媒体范围任务书包含 Windows、macOS、Android，以及视频、音频、图片。桌面视频作为 MVP；其余作为后续毕设里程碑保留。调整正式交付范围需与导师核对。
智能功能要求基础处理稳定后完成至少一种 AI 视频解析原型。选择“带时间戳的主题识别与分段建议”作为可测原型；完整 Agent 生态作为产品后续目标。
调度能力任务书写有暂停、恢复、抢占、优先级与资源限制。定义各自语义后分阶段实现。MVP 先暂停队列启动；执行中暂停、抢占和崩溃后续作分别验收。
历史经验的复用顺序

先复用源文件检查、输出保护、临时文件发布、硬件编码回退和数据库迁移的测试思路，再审查可复用代码。旧分支的架构记录与发布描述不作为新 main 的已实现证据。

本次已阅读开题报告、已完成任务书和告知书；模板与往届案例只做文件清点。个人身份字段未纳入本计划。

03 / 技术方案

Flutter + Rust Worker + FLL

Flutter 同时服务桌面和 Android 界面。Rust Worker 管理任务生命周期，FLL 封装媒体操作。通过独立进程把媒体执行故障限制在单个宿主内，使用同一套任务协议连接各类调用入口。

Flutter UIMVP · 导入 / 配置 / 任务 / 结果
内置 Agent后续 · 模型连接 / 计划 / 工具调用
CLI / MCP后续 · 外部 Agent / 自动化
统一任务接口 · 请求校验 · 本地认证 · 事件与快照
Worker / FEngine唯一任务状态源 · 队列 · 进程管理 · 资源预算 · 取消 / 重试
持久化任务状态与事件；按资源预算启动处理宿主
隔离的 FLL Host 进程加载 FLL 动态库 → libav / 可选格式后端
SQLite + 工作目录任务记录 / 分析缓存 / 临时输出
模块建议选择与理由实现边界
客户端Flutter / Dart；视图、应用交互、Worker 网关分离。界面状态局限于筛选、选择、表单等；任务真值从 Worker 获取。具体状态管理库在实施时按最小需求锁定。
WorkerRust；SQLite 持久化；单独进程按需启动。统一任务创建、调度、事件、资源与输出发布状态；重解析和编码进入子进程。
通信建议桌面先用 loopback HTTP/JSON + SSE；协议带版本、request_id、task_id、事件序号。仅绑定回环地址；随机端口与本机私有凭证；验证来源、身份与输入。重连使用快照补齐，不能仅依赖事件。Android 复用模型，传输可按平台调整。
FLLRust 动态库，版本化 C ABI；FFmpeg/libav 为首个执行后端。分析、能力检测、处理方案、执行和结果校验。句柄、错误码、缓冲区所有权明确；不持有第二套全局队列。
动态分发Windows 为 .dll，macOS 为 .dylib，Android 为 .so。“一个核心接口”允许随包分发匹配版本的依赖库；先做双桌面打包加载试验，再扩大功能。
AndroidFlutter + 平台适配；评估 Media3/MediaCodec 或已有 libav 后端的适用范围。独立处理内容 URI、授权和后台服务。Media3 可复用转码能力；平台生命周期不能直接照搬桌面守护进程。
Agent 与模型后续以单独模块接入云端服务或本地模型；CLI/MCP 共用 Worker 能力。模型输出结构化任务请求；Worker 再次验证。模型能力检测和错误提示先于多供应商扩张。

关闭与退出的语义

  • 关闭窗口：UI 退出，已提交任务继续。
  • 重新打开：连接既有 Worker，获取任务快照。
  • 正式退出：提示正在执行的任务，用户选择完成后退出或取消并退出。
  • 宿主崩溃：当前任务失败可重试，队列和 UI 继续可用。
  • Worker 异常：受管宿主停止，重启对账；中断任务可从头重试。

实施中的四个重点

  • 解码器故障也可能发生在分析阶段，分析同样进入隔离宿主。
  • 先串行执行，再按实测扩展并发；进程隔离不能消除 CPU、内存和磁盘竞争。
  • 临时文件与目标位于同一文件系统，校验后发布；跨卷导出单独处理。
  • 发布验收检查动态库、ABI 和依赖实际加载，开发机可运行不足以证明安装包可用。

技术依据：Flutter 桌面支持 · Media3 Transformer · HandBrake 进程隔离。具体库版本与构建许可清单在依赖锁定时核验，本计划不提前宣称兼容。

每个阶段，都有完整的用户链路

默认显示所有阶段。可单独查看某阶段；打印时自动展开全部内容。阶段退出条件优先于日历进度。

技术贯通：处理一个真实视频

建议 1–2 周 · 开发验证阶段

P0
打开最小客户端→选择测试视频→查看信息→使用固定预设压缩→检查输出

开发重点

  • 建立 Flutter → Worker → Host → FLL 的真实处理链。
  • 实现 analyze / execute / cancel 的最小协议和进度事件。
  • 先支持一组 SDR 视频输入与 MP4 输出；包内加载动态库。
  • 同一简单样本在 macOS 与 Windows 分别跑通。

异常交互

依赖缺失显示组件诊断；不支持的媒体明确拒绝；编码失败显示原因并保留可定位日志。分析过程有状态反馈。

交付物

可启动的双端技术包、协议草案、样本与原始验证记录。

退出条件：两平台真实压缩成功；取消可以停止处理；主动终止宿主后 UI 与 Worker 可用；确认打包中的 FLL 实际被加载。

产品 MVP：可靠的视频压缩

建议 3–4 周 · 第一版可交给用户使用

P1
拖入多个视频→查看分析与支持状态→选择清晰度 / 目录→加入队列→后台处理→查看结果

用户能完成什么

  • 选用“保留更多细节 / 均衡 / 更小体积”等预设，了解质量取舍。
  • 批量执行、暂停后续任务、取消当前任务、单独重试失败项。
  • 关闭窗口后继续处理，再打开看到真实进度。
  • 查看输出体积、节省比例和路径，打开文件或所在目录。

开发重点

媒体信息、质量压缩、串行队列、任务持久化、事件重连、临时输出、校验和安全发布。采用已验证的软件编码基线；硬件加速按设备能力逐步开放。

异常交互

源文件变更需重新分析；磁盘不足提示释放空间；重名自动生成新名称；无收益的压缩明确提示结果较大，原文件始终保留。

退出条件：目标样本矩阵全部通过或明确拒绝；10 个混合样本连续排队无状态丢失；取消与失败不发布残缺结果；两桌面平台通过关窗重连与宿主故障测试。

媒体工具箱：转换、规则分段与批处理

建议 4–5 周 · 扩展成熟处理能力

P2
导入媒体→选择压缩 / 转换 / 分段→设置输出规则→预览处理方案→批量导出

用户能完成什么

  • 转换常用容器与编码；兼容时直接转封装。
  • 目标体积压缩，明确预计值和不可满足的条件。
  • 按时长、指定区间、章节分段；显示边界预览。
  • 处理首批音频和图片，复用输出规则与队列。

开发重点

处理目标与执行参数分开；统一格式能力表；支持精确转码切分和关键帧快速切分。任务计划可复用，导出命名一致。

异常交互

选择快速分段时提示边界可能偏移；严格边界采用转码。目标体积过小时解释质量/音频开销约束；未支持音轨或色彩组合不静默丢弃。

退出条件：转换结果满足声明格式；分段范围、时长与音画同步可复核；目标体积模式有实测误差与重试上限；首批视频/图片/音频各有真实样本和输出验证。

多端与毕设：形成可验证的完整系统

建议 4–5 周 · Android 与跨平台可靠性

P3
手机选择媒体并授权→显示可用处理方式→开始任务→通知 / 前台查看进度→保存或分享结果

用户能完成什么

  • Android 上完成导入、压缩、常用转换和结果管理。
  • 桌面端使用可解释的队列优先级与资源限制。
  • 按平台已实现能力使用执行暂停、恢复与抢占。
  • 查看任务中断原因，并选择重试。

开发重点

Android 存储访问、URI 授权、前后台状态和编解码适配；先做实机纵向链路，再补界面。公共任务模型保持一致，平台能力可以不同。

异常交互

系统回收或强行停止后显示中断状态并对账；授权失效重新选择文件；资源不足时降低并发。移动端不承诺永久后台存活。

退出条件：三平台都有可安装演示版本；真机完成基础流程与生命周期测试；暂停/恢复/抢占的实现范围有表格和故障记录；论文设计章节能对应真实实现。

智能处理：先理解内容，再自动执行

建议 3–4 周完成受限原型 · 完整 Agent 后续迭代

P4
选择视频与模型→设定分段目标 / 费用上限→分析内容→查看候选边界→自动或确认导出→检查与修正

先交付可评估原型

  • 对有清晰语音的样本生成带时间戳的主题摘要和分段建议。
  • 使用 P2 的分段引擎执行，保留段落来源与边界依据。
  • 默认预览；用户可为明确任务启用自动导出。
  • 提供最小 CLI，再以 MCP 暴露同一组稳定操作。

Agent 接入范围

第一批工具：analyze、plan、submit、status、cancel、list_outputs。内置 Agent 通过 Worker 调用；按需读取转录与局部视频帧。先验证一个云端适配与一个可用本地配置。

异常交互

模型不可达时基础处理仍可用；模型不支持视觉时标明仅语音理解；费用达到上限停止新增推理；已提交的媒体任务继续执行。

长期产品：可组合的媒体能力

毕业设计之后持续迭代 · 由用户数据决定优先级

P5
导入一批混合媒体→描述目标→复用分析索引→组合处理流程→后台交付结果

目标能力

  • 语音、画面和镜头联合判断分段；支持内容搜索与事件定位。
  • 分析缓存按素材指纹、模型和参数失效，避免反复全量推理。
  • CLI/MCP、内置 Agent 与任务模板具备一致语义。
  • 围绕真实素材扩展特殊格式、兼容转换和有限修复。

插件与研究方向

Skill 先作为任务操作说明；插件在实际扩展需求出现后提供版本、能力和权限声明。垂直研究优先比较分段质量、特定内容压缩策略和格式诊断成功率。

产品指标

任务完成率、首次使用成功率、人工修正时间、资源开销、每小时媒体分析费用与用户重复使用率。

演进依据：真实任务暴露的缺口优先；新后端需用同一批样本证明质量、速度、成本或支持范围的收益后再接入。
05 / 第一版的实施顺序

MVP 的交付物，是一个可用的压缩软件

顺序开发内容界面与用户行为完成证据
M1 · 输入与分析文件句柄/路径验证；结构化媒体信息；支持状态；分析任务隔离。拖入或选择文件，逐项显示分析中、可处理或不支持及原因。中文、空格、长路径、无权限和损坏文件用例；正常样本信息与参考探测结果一致。
M2 · 压缩执行固定软件编码基线，质量预设，进度、取消、输出方案。选择预设与目录，看到预期取舍，开始处理。预计体积带估算标识。真实文件压缩；检查时长、分辨率、轨道与解码；取消能停止受管进程。
M3 · 任务与状态SQLite 任务记录、串行队列、事件序号、快照和幂等提交。排队、取消、暂停后续启动、重试失败项；重复点击不产生重复任务。排队顺序正确；重连快照正确；状态迁移与数据库保持一致。
M4 · 输出可靠性源文件复核、可用空间检查、临时输出、结果验证、同卷发布。原文件保留；输出自动避让重名；失败明确原因和可采取操作。磁盘写入失败、源变更、取消、宿主异常时不发布残缺正式结果。
M5 · 生命周期Worker 单实例与发现机制；后台独立存活；受管宿主退出策略。关闭窗口继续任务；重开恢复展示；正式退出可取消任务或等待结束。真实关闭 UI、终止 Host、终止 Worker 与重启后的对账记录。
M6 · 安装与验收双桌面打包、依赖定位、版本信息、诊断日志和基本资源限制。安装后无需开发环境即可完成压缩；错误可复制脱敏诊断。macOS 与 Windows 安装包实机验证；记录实际依赖与构建版本。

MVP 的四个页面

  1. 处理：文件列表、预设、输出位置、开始按钮。
  2. 任务：排队与执行状态、进度、取消、重试、队列暂停。
  3. 结果：输入/输出信息、节省体积、打开文件和目录。
  4. 设置：默认输出目录、关闭窗口行为说明、资源限制、诊断。

明确的状态与操作

queued → running → validating → succeeded

各阶段可进入 failed 或 canceled；后台异常遗留任务记为 interrupted 并等待处理。

重试创建新执行记录，保留前次原因。进度未知时显示当前阶段；只有结果通过验证并发布后才能显示“完成”。

先做出来，再扩展。

MVP 固定支持范围、简单预设和串行队列。目标体积压缩、通用格式转换、执行中暂停、复杂抢占和智能分段在后续阶段交付；原文件保护、取消、结果校验和前后台分离从第一条链路开始建立。

暂停与恢复的具体含义

能力用户看到的行为阶段与约束
暂停队列当前任务继续，后续任务暂不开始。P1。状态持久化，恢复时继续取队列。
执行中暂停当前编码停止推进，随后继续同一次执行。P3。按后端验证协作式暂停；硬件编码和资源释放行为需要单独测试。
优先级与抢占重要任务优先；必要时让正在执行的任务让出资源。P3。队列重排与运行中抢占分别实现。若只能取消重启，必须明确标注其代价；与任务书要求核对。
异常恢复重启后知道哪些完成、哪些中断；安全清理或重新执行。P1 起实现对账。编码断点续作需要可恢复输出与后端支持，另立实验，不能用进度持久化代替。
06 / 能力范围可验证

按真实样本扩展格式，而非只列扩展名

以下是建议支持矩阵，实施后以安装包实际能力为准。输入容器、内部编码、像素格式、色彩、音轨与输出编码要分别记录；文件扩展名只帮助识别入口。

阶段建议首批范围边界与验收
P0–P1 视频优先验证 MP4/MOV 内 H.264、8-bit SDR、常见 AAC 音轨；输出 MP4/H.264/AAC。明确处理无音轨视频。保留显示方向与时长；多音轨让用户明确选择；HDR、10-bit 和未验证组合给出不支持原因。对应编码器能否随包分发，在构建选择时核验。
P2 视频转换逐步验证 MKV/WebM、HEVC/VP9/AV1 的实际解码组合；增加受控输出预设、转封装和区间导出。读和写能力分别声明；变帧率时间戳、旋转、字幕轨保留策略、HDR 处理策略单独验收。
P2 音频与图片首批音频候选 WAV/FLAC/MP3/AAC；图片候选 JPEG/PNG/WebP。按真实构建能力收敛。区分音频码率压缩与动态范围压缩；图片记录透明度、方向、色彩和元数据保留策略。“无损”需说明指编码、像素还是直接复制。
P2 后的特殊格式候选 HEIF/HEIC、AVIF、动画 WebP/GIF、相机与录屏导出的特定容器组合。按用户样本与频次选优先级。每类记录解码后端、输出范围、质量损失和平台差异；专有加密格式不作通用支持承诺。
P5 兼容与修复先提供可解释诊断；针对确有可恢复数据的具体问题提供受限修复。修复必须有前后验证和失败原因；损坏结构与缺失数据分开判断，保持源文件不变。
目标体积压缩的承诺要可验证。

先按时长、音频预算与封装开销生成参数，必要时使用两遍编码或有上限的重试。将“预计约 20 MB”与“必须小于 20 MB”分开；严格上限无法满足时说明原因。单一质量参数不能保证最终体积。

08 / 用证据完成毕业设计

每个承诺，都对应一个测试或实验

研究或验收问题方法保留证据
压缩是否有价值同一素材比较不同预设；记录输出大小、耗时、可用质量指标和人工观察。质量指标按相同尺度与色彩条件计算。输入指纹、编码参数、输出信息、机器配置、重复运行结果；不可只挑最优样本。
界面是否与任务解耦分别关闭 UI、终止 Host、终止 Worker；再连接并核对状态。测量高负载下交互响应。事件序列、数据库状态、输出文件状态和演示录像。
任务是否可靠磁盘不足、源文件变化、输出冲突、取消、重复提交、异常中断和版本不匹配。错误分类、预期状态、实际状态、清理/恢复行为与通过记录。
三端是否一致共享测试样本与任务语义，分别记录支持矩阵；Android 增加 URI 授权与生命周期场景。各平台构建标识、设备、输入输出、支持或拒绝原因。
智能分段是否节省时间人工标记主题与可接受边界区间；比较固定时长、停顿规则与语义方法。先用 10–20 段代表性素材试验，再决定扩样。边界误差、断句/断动作比例、人工修正时间、漏段与重复、推理费用；试验数据与调参数据分开。
普通用户能否顺利完成邀请少量目标用户完成压缩与分段任务，记录成功率、误操作和必要帮助。匿名化观察记录与修订依据；小样本结果说明局限。
